STEP 2 — THE TOKEN-LEVEL LITERAL PROOF
================================================================================
The string lives in the COMPRESSED scatter region, so a same-length replacement
is only safe if two conditions hold, and neither is visible in the bytes:
  1. every replaced stream byte is a LITERAL, not a token parameter;
  2. no LATER back-reference reads from the output positions being changed.

A decoder with per-output-byte provenance was written from the log-105 rules
and cross-checked against reconstruct_decompress for output equality:

ALL TWENTY BYTES ARE LITERALS, contiguous in the stream, and NOTHING LATER

difference of exactly 0x2c. The first-ranked target held; no fallback to the
second-ranked key-policy entry was needed.

================================================================================
STEP 5 — A CHECK THAT FAILED, AND WHY THAT WAS RIGHT
================================================================================
The first validation run reported:

  FAIL the decoded regions differ in exactly the intended positions
       — 19 bytes at 0x882..0x895

Nineteen, not twenty. The artefact was correct and MY CHECK WAS WRONG. The two
strings coincide at one position:

  $ positions where the two strings coincide: [18] ['F']
    ROG FALCHION ACE HFX
    UNTESTED FALCHION FW
                      ^ both 'F'

A byte that did not change is not a defect. The invariant that matters is
CONTAINMENT, not a count, so the check was replaced by two that state it
precisely:

  NO decoded byte outside the intended span changed          <- the real
                                                                propagation test
  every differing byte is accounted for by the replacement   <- 19 differ +
                                                                1 coincide = 20

The count check would have passed for the wrong reason on a different
replacement string, and failed for the right reason here. Replacing it with
containment is the correction; loosening it to "19 or 20" would not have been.

================================================================================
STEP 7 — THE FAILURE DEMONSTRATIONS
================================================================================
A validator that only ever passes proves nothing. Both required failure modes
are demonstrated on a synthetic stream small enough to check by hand:

  STREAM  b"\x1dABCD\x04"  ->  b"ABCDABC"
  control 0x1d: literal field 5 (emits 4), bit 3 set, copy field 1 (emits 3)

  PROPAGATION. Output byte 0 is a literal that the back-reference copies to
  output byte 4. `propagation_reads(decoded, 0, 1)` returns ((0, 4),) — the
  detector fires. And it is not merely theoretical: patching that literal to
  'Z' yields b"ZBCDZBC", and the diff is [0, 4] — ONE PATCHED LITERAL CHANGED
  TWO OUTPUT BYTES. A test asserts exactly that.

  A LITERAL WITH NO LATER READER does not propagate: patching output byte 3
  changes only byte 3, and `propagation_reads` returns empty.

  TOKEN-STRUCTURE CORRUPTION. Changing the control byte from 0x1d to 0x2d
  alters the copy field, and the decoded token tuples differ — the "token
  structure is unchanged" check would fail. Corrupting the distance byte
  changes the output wholesale. Truncation raises rather than returning short,
  and a back-reference before the start of output raises.
