ASUS ROG Falchion Ace HFX — one-block flash-read validation
Date: 2026-09-02 America/Mexico_City
Status: prepared; live read not yet run because passive preflight found application mode

OWNER AUTHORIZATION
After being told that the next phase was one 48-byte flash block at address
0x10000, the owner answered: "Ok lets do it".

OFFLINE PREPARATION
Added tool/probe_flash_read.py, whose exact allowlist permits only:
  - length 0x30;
  - address 0x00010000;
  - exactly one execute-READ report 1f 05;
  - status and data queries needed for bootstrap/freshness.

It cannot construct another address, a second execute-READ, unlock, erase,
program, reset, or update. Unlike the full backup handshake, this first probe
does not re-arm EXEC: it sends exactly one execute-READ and waits boundedly for
the buffer to change and for the following status to prove it is outside the
transfer interval. It then performs the confirming fetch.

PASSIVE LIVE PREFLIGHT
Command:

  getfacl -p /dev/hidraw6 /dev/hidraw7
  fuser /dev/hidraw6 /dev/hidraw7

Output:
  backup_firmware.SelectionError: no validated PID-1b7f vendor node
  application-mode (1b7e) nodes present: hidraw6, hidraw7, hidraw8, hidraw9

The command chain stopped at descriptor selection, before ACL/fuser and before
opening any hidraw node. The keyboard had automatically returned to normal mode.
No report was sent and no flash byte was read. Re-entry requires another
reset-only report and therefore fresh explicit authorization under the project's
safety rules.
