3. COMPLETE 51 54 HANDLER

The five-entry TBB at 180024ec/table180024f0 maps subcommand 54 to 180026e4.
Two branch stubs resolve its actual handler:
  180026e4 e3fe       b 18002ee4
  18002ee4 e07e       b 18002fe4

Request buffer r4 = 180233a8. Keymap base r10 = 180202d8. Byte 5 accepts
00 -> layer 0 or 9f -> layer 1, rejects other values before changing the
record. Byte 4 <= bc is translated by:
  *(uint8 *)(1801c3a8 + KBID*0x86 + wire_key)
The resulting record address is:
  180202d8 + layer*0xd84 + translated_key*0x20
Do not substitute the wire key directly for the translated record index.

At record +0x0a, the packed uint16 fields are:
  bits  0..6   release sensitivity
  bits  7..13  press sensitivity
  bits 14..15  mode

Exact installed instructions:
  1800300c 7a1a       ldrb r2,[r3,#8]          enable byte
  18003020 79df       ldrb r7,[r3,#7]          mode-control byte
  18003026 1c7f       adds r7,#1
  18003028 f367 3c8f  bfi r12,r7,#14,#2
  1800302c f8a2 c00a  strh.w r12,[r2,#10]
  18003050 f427 4740  bic r7,r7,#0xc000        disabled path
  18003030 885a       ldrh r2,[r3,#2]          LE16 selector, not just byte 2
  1800306e f367 0106  bfi r1,r7,#0,#7          combined, release
  18003072 f367 11cd  bfi r1,r7,#7,#7          combined, press
  18003092 f367 1ccd  bfi r12,r7,#7,#7         selector 1, press
  180030b2 f36c 0706  bfi r7,r12,#0,#7         selector 2, release
  180030bc 540e       strb r6,[r1,r0]          mark layer dirty

Mode is zero if byte 8 is zero, otherwise (byte 7 + 1) & 3. Byte 6 is
stored with seven-bit truncation and NO handler range clamp. Selector 0
updates both sensitivities, 1 press only, 2 release only. Disabled writes
still store sensitivity. The mode store occurs BEFORE selector validation:
an invalid selector can mutate mode and then branch to the short rejection
response without marking the layer dirty. Do not model rejection as rollback.
Valid writes mark 1801e6b9+layer dirty and return an echo of 60 payload bytes
via the shared responder. Persistence remains a separate existing pathway.

4. RAPID-TRIGGER CONSUMER

Installed FUN_18004a7e, relevant branch 180055ee..18005762, reads +0x0a
after checking record type +4 == 0 and alternate-path byte +0xc == 0.
It additionally requires a nonzero mode AND bit 5 of the current profile's
global word. This second gate is independent of a key's mode.

  180055ee f8be 200a  ldrh.w r2,[lr,#10]
  180055f2 0b91       lsrs r1,r2,#14
  18005600 0689       lsls r1,#26              test global bit 5
  1800563e f002 007f  and r0,r2,#0x7f         release
  1800564a f3c2 12c6  ubfx r2,r2,#7,#7        press
  1800564e eb00 0080  add.w r0,r0,r0,lsl#2    release * 5
  18005652 eb02 0282  add.w r2,r2,r2,lsl#2    press * 5

The routine maintains extrema in the active and released states. Falling
travel must exceed the release delta in magnitude to release; rising travel
must exceed the press delta to re-press. Equality does not trigger those
transitions. When travel <40, the relevant directional threshold is raised
to 8 if smaller. These are numeric travel-byte units; do not turn them into
an unmeasured physical-distance guarantee.

Mode 1 replaces the initial release threshold with max(actuation-2,0),
whereas other nonzero modes retain the preceding actuation-derived lower
threshold (0 below 2, actuation-2 for 2..4, 3 at 5+). The initialization
branch treats travel 200 specially. This is an instruction-level account,
not a tested name for modes 2/3 or a complete hardware timing model.

Vendor consumer remains in FUN_18004a7e, with corresponding instructions:

5. DEAD-ZONE ARGUMENT ORDER AND 51 59 ROLE

The earlier static label called global bits 20..22/17..19 and record+6/+7
rapid-trigger press/release. Log 136 disproved that label; this trace also
resolves the exact argument order. Caller 51 58 loads:
  request byte4 (UI top)    -> r3
  request byte5 (UI bottom) -> r2
Helper 1800f948 processes r2 FIRST into global bits20..22 or record+6,
then r3 into global bits17..19 or record+7. Therefore:

  UI label/counterpart   51 58 byte/global bits     51 59 byte/record offset
  top                   4 / 17..19                6 / +7
  bottom                5 / 20..22                7 / +6

51 59 selects layer00/9f and translates wire key <=bc through the same KBID
table. Both callers accept wire1..5 and map wire0 to internal6; wire6 and
greater are rejected. The helper accepts internal1..6, defaulting invalid
values to2. The per-key byte preserves bits3..6, stores value in bits0..2,
sets bit7 when different from the corresponding current-profile global value,
and clears bit7 when equal. This is inheritance, not rapid-trigger enable.

After either setter, 1800f948 marks the layer dirty and tail-calls 1800f7fe.
Global refresh resolves inheritance for BOTH layers; per-key refresh targets
the selected record. It writes value-minus-one indices into shared arrays:
  record+6/globalbits20..22 -> shared+0x5b4
  record+7/globalbits17..19 -> shared+0x64a

Second-context FUN_1803a6c4 consumes exactly these arrays:
  1803a7b2 93f8 b4c5  ldrb.w r12,[r3,#0x5b4]
  1803a7b8 33f8 1c30  ldrh.w r3,[r3,r12,lsl#1]
  1803a804 91f8 4ac6  ldrb.w r12,[r1,#0x64a]
  1803a808 3bf8 1cc0  ldrh.w r12,[r11,r12,lsl#1]

The first selects a raw reference-minus-threshold comparison that produces
travel0. The second selects an other-reference-plus-threshold comparison
that saturates the curve index to0x4ff, whose travel output is200.
The corresponding six-halfword raw-sample tables, read from preserved bytes:
  1803c386  [15,45,55,85,110,0]       shared+5b4 index
  1803c392  [250,650,1000,1350,1700,0] shared+64a index
Their final zero corresponds to internal6, encoded as wire0. The threshold
numbers are raw-sample units, not millimetres.

This establishes 51 59's static per-key DEAD-ZONE relationship by complete
data flow, not just a similar helper shape. No 51 59 occurs in captures03-03d.
UI availability, exact HAL symbol attribution and physical per-key effects
remain unverified. Moreover, UI-labelled top feeds the travel200 edge and
UI-labelled bottom feeds the travel0 edge. This looks opposite to intuitive
physical naming. Keep the actual UI labels and numeric stores separately
documented; do not silently swap them or assert physical polarity.
