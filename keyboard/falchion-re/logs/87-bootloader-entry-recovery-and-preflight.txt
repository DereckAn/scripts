APPLICATION-SIDE PROOF

Candidate B FUN_180160d8 receives a 64-byte endpoint buffer. When bytes 0..6
are:

  7b aa 41 53 55 53 aa

it performs:

  *(uint32_t *)0x20000ffc = 0x73207320;
  *(uint32_t *)0x40022000 |= 0x8000;
  delay(100);
  reset();

The reset path is distinct from Candidate B's top-level vendor-HID command
0xb0. That branch requires report[1] == 0, report[2:4] == 0 and
report[4:9] == "reset", then writes AIRCR 0x05fa0004 without first writing the
force-boot magic. It is an ordinary reset, not bootloader entry.

The magic receiver is installed indirectly in the low-level USB endpoint
interrupt callback table. FUN_18016908 references Thumb pointer 0x180160d9 at
0x18016d4c while initialising the endpoint/IRQ structures, including the
64-byte endpoint configuration.

UPDATER-SIDE PROOF

FW_Update_Tool_M605.exe is a managed wrapper. MainWindow.UpdateFW reads
config.ini and launches FW/peripheral_fwu_pro.exe using Cmd 1, the BIN path and
Cmd 2. It does not build the report itself.

In peripheral_fwu_pro.exe, the "Jump to Bootloader" block is at
0x00407231..0x0040735c. It:

  1. zero-initialises a vector to the configured application packet length;
  2. calls FUN_004054e0(vector, selector=4, 0, 0);
  3. sends that vector through FUN_00401b30;
  4. polls for the bootloader PID and prints "Entry Bootloader Success!".

FUN_004054e0 selector 4, with the official lower-case "m" mode, writes exactly:

  payload[0] = 0x7b
  payload[1] = 0xaa
  payload[2] = 0x41
  payload[3] = 0x53
  payload[4] = 0x55
  payload[5] = 0x53
  payload[6] = 0xaa

All remaining bytes retain the zero fill. This independently matches the
Candidate B receiver.

HID FRAMING PROOF

The current application interface 1 descriptor is:

  06 00 ff 09 01 a1 01 09 02 75 08 95 40 15 00 26
  ff 00 81 02 09 03 75 08 95 40 15 00 26 ff 00 91
  02 c0

It declares usage page 0xff00, usage 1, a 64-byte Input, a 64-byte Output and no
Report ID.

HidInterruptHandle.dll InterruptTransfer_WriteLen at 0x100013a0 allocates
payload_length + 1, writes the separate report_id argument to byte 0, copies the
payload to bytes 1..length, and calls WriteFile for the combined length. Thus
the Linux hidraw write corresponding to the updater is exactly 65 bytes:

  00 | 7b aa 41 53 55 53 aa | 57 zero bytes
