THE OVERCLAIM
================================================================================
ORIGINAL WORDING — tool/map_usb_routing.py, the EP 0x0f route's kind_basis,
which propagated verbatim to notes/usb-routing.json, notes/usb-routing.md and
the tool's stdout, and so into log 107's STEP 8:

  "interface 4's record is the only one with the OUT bit set and no IN
   endpoint, matching the host's OUT-only interface 4; its 327-byte report
   descriptor is byte-identical to the host's"

WHY IT IS UNPROVABLE FROM THIS REPOSITORY. Interface 4 was unbound on the host,
so no driver ever exposed a hidraw node for it and no raw report-descriptor
bytes for it were ever captured:

Log 09 holds hidraw0-3 only. Log 15 holds zero lines of raw hex; for interface 4
it holds lsusb's DECODED item listing and nothing else. FINDINGS.md line 106
independently records that interface 4 "remained unbound". There is therefore no
byte source in this repository against which interface 4's descriptor could have
been compared, and the claim could not have been made from evidence.

THE CORRECTION
================================================================================
CORRECTED WORDING, now in tool/map_usb_routing.py and regenerated into
notes/usb-routing.{json,md}:

  "interface 4's record is the only one with the OUT bit set and no IN
   endpoint, matching the host's OUT-only interface 4. Its 327-byte report
   descriptor at region+0x13b was located STRUCTURALLY, is well-formed (the HID
   item walk consumes exactly 327 bytes), and its parsed item sequence matches
   the host's parsed listing item for item. BYTE-IDENTITY CANNOT BE CHECKED:
   interface 4 was unbound on the host, so no raw report-descriptor bytes for
   it exist in this repository — log 09 captured hidraw0-3 only and log 15
   preserves lsusb's parsed items, not bytes"

THE BOUNDARY IS NOW PINNED BY CHECKS, not only by prose. Three were added to
tool/map_usb_routing.py; no existing check was weakened or removed.

$ python3 tool/map_usb_routing.py
  PASS interface 4 has NO raw host bytes in this repository — byte-identity is not checkable — interface 4 was unbound on the host; log 09 captured hidraw0-3 only and log 15 preserves lsusb's parsed items, not bytes
  PASS interface 4's descriptor is well-formed and the item walk consumes exactly its declared length — 155 items over 327 bytes at region+0x13b
  PASS interface 4's PARSED item sequence matches the host's parsed listing (item comparison, not byte comparison) — 155 firmware items vs 155 host items
  RESULT routing_ok=True checks=27
  [exit 0]

The check count moved from 24 to 27 and every prior check still passes. The new
positive result is worth stating plainly: the firmware's descriptor walks into
exactly 155 HID items and every one of them — kind and data bytes — matches the
155 items lsusb decoded. That is strong evidence the descriptor is the one the
host saw. It is an ITEM comparison. It is not a byte comparison, and the tool
now says so in the same breath.

  - a missing host section in notes/usb-descriptors.txt raises rather than
    silently comparing against an empty listing
