DESIGN
  * Parsing (parse) may inspect an unknown image and fails closed with
    ImageFormatError; it applies no pass/fail policy.
  * Validation (validate) reports the known constraints and names every
    region it could not check (skipped_containers, skipped_word_sums).
  * Source policy (require_supported_source) refuses any image whose
    SHA-256/base/size tuple is not allowlisted. Mutation tooling must call
    it; read-only analysis must not.
  * Every offset is a logical flash offset. File indices exist only inside
    ImageView.index, which is the single translation point.
  * Record lengths are read from the image being parsed. No vendor 1.00.58
    length is reused for another release.
  * to_dict() is the machine-readable result, so Phase 2+ never parses stdout.

NEW FACTS ESTABLISHED IN THIS PHASE
  1. The installed 1.59 record[1] length is 0x1e780; the vendor 1.00.58 value
     is 0x1e754. The application record grew by 44 bytes. record[0] length
     (0x58ac) and both load addresses (0x60011000, 0x60021000) are unchanged.
  2. The installed dump's logical range [0x61000,0x71000) is byte-identical to
     the vendor 1.00.58 backup range [0x61000,0x71000) and to its primary
     bootloader region [0,0x10000); all three hash to
     4a4568b61bc245397b0ede6f285eb1bd8a7fa2018bc1373bc05e73eabb0f686a. The
     bootloader already under static analysis therefore exists on the device as
     the mirrored copy. This does not cover the unread installed primary region
     [0,0x10000), which container the device actually booted, or ROM behaviour.
  3. The additive word-sum guard of the mirrored bootloader copy validates in
     both images: logical [0x61000,0x71000), guard word at 0x70ffc, value
     0xfb665ae3 — the same value the primary region stores at 0x0fffc. The
     library reports this as a third word-sum region, 'bootloader_mirror',
     which analyze_candidate_integrity.py does not cover.
  4. The SN_FWIN +0x8 string is 'v1.0.00' in both images. It is the container
     format version and does not track the ASUS release version.

ASSUMPTIONS AND DELIBERATE LIMITS
  * No existing analyzer was refactored. The plan permits refactoring only
    where regression tests preserve known output; analyze_sonix_firmware.py and
    analyze_candidate_b_tables.py have no tests at all, and the two covered
    analyzers are the reference implementations that logs 74-92 were produced
    with. Instead the new library is self-contained and four AnalyzerParity
    tests prove it agrees with both on the two real images, so a later
    refactor can be a separate reviewed change.
  * chunked_crc_sum keeps the source's word-aligned pointer advance
    (pos += size & 0xfffffffc) for bit-exact parity with the audited
    implementation. It can only differ from size on the final chunk, after
    which nothing is left to read.
  * SP_RANGES, EXPECTED_CONTAINER_SIZE, the container table and the
    application region bounds are carried over unchanged from
    analyze_boot_structures.py; this phase re-homed them, it did not re-derive
    them from the bootloader.
  * validate() reports internal consistency only. The UNRESOLVED lines
    (FUN_000029d4, the top-level selected-entry comparison, ROM/first-stage)
    are attached to every result so a pass is never read as 'this boots'.
  * The mirrored copy at [0x61000,0x71000) carries a third SNC7320A/SN_BCFG
    header at 0x61000 whose bootloader pointer is 0x60001000. It is not
    modelled as a container here; the container table still holds exactly the
    two the bootloader is known to consult (0x0 and 0x60000).
